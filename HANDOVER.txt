【5】技术分层（改代码前必须知道）
----------------------------------------------------------------
engine 里除 composer.py 外，一律不调用 LLM，必须是纯函数。
llm.py 是唯一允许发网络请求的地方。
main.py 只做请求映射，不含业务逻辑。
所有阈值放 config.py，不许散落在函数里。

这条分层是整个项目的骨架。破坏它，测试就跑不动，答辩也讲不清。


【6】六个核心设计决策（答辩会问"为什么"）
----------------------------------------------------------------
(1) 三层真相
    每条事实有三个层次：truth（客观）/ belief（NPC 相信的）/ utterance（说出口的）。
    NPC 可以"真诚地说错话"——他说的是自己相信的错版本，不算撒谎。
    玩家要分辨的不是谁在骗人，而是谁被误导了。
    剧本里 f03 是唯一样例：周砚青相信争吵持续到 23:10，实际 22:45 就停了，
    误导他的人是沈玉兰。

(2) 知识边界靠数据不靠 prompt
    每条 fact 有 holders 列表，检索时先硬过滤 holders，
    再做主题匹配和排序。不在 holders 里的人，任何问法都检索不到。
    这是"不可能被模型常识绕过"的设计。

(3) 压力机制是唯一的手感来源
    玩家出示线索 → 目标 NPC 压力 +0.25（上限 1.0）
    → 风险值下降 → 动作从"骗"降到"躲"再降到"说"。
    风险公式：risk = sensitivity - 0.6 * pressure，clamp 到 0~1
    动作判定：risk <= 0.55 说；risk >= 0.75 且 lie_propensity >= 0.5 骗；否则躲。

(4) 撒谎倾向不参与风险计算
    早期版本写成 risk = sensitivity * (0.5 + 0.5*lp) - 0.6*pressure，
    这等于"越老实的人秘密越不危险"，导致压力 0 时 9 条事实白送。
    lie_propensity 只决定"骗"还是"躲"，不改变危险度。这条有回归测试锁着。

(5) evade 不能看到事实原文
    早期 composer 在 evade 时把 fact.text 塞进 prompt，
    模型就用含糊语气把事实复述了一遍，压力机制直接废掉。
    现在 evade 只给"话题方向"，不给任何具体内容；
    校验时 evade 的 allowed_text 返回空串，出现任何时间数字都判漏嘴。

(6) 同一张线索对同一 NPC 只能出示一次
    唯一键是 (clue_id, npc_id)。否则玩家刷同一张线索就能把压力拉满。

【8】踩过的坑（都是真实发生过的，别再踩）
----------------------------------------------------------------
(1) requirements.txt 里注释与依赖粘连
    写成 "pytest==9.0.2# Web 接口" 一行，pip 解析失败。
    本地不暴露是因为包早就装好了。
    → 每次改 requirements 都要在干净 venv 里跑一次 pip install -r。

(2) 码道的自述比代码乐观
    它报"已移除全部光晕"，实际 grep 发现五处还在，git stat 显示 +9 -0。
    → 凡是"已删除""已替换"这类说法，必须用 grep 或 git show 验一遍。

(3) 线索不可达
    c08 挂在 f03 上，但检索永远先返回 f02，导致这张线索永远解锁不了。
    → 加线索前先用检索层跑一遍，确认它真能排到第一条。

(4) 开局只有一条线索，压力推不到 0.5
    只能重复出示同一张刷压力，机制形同虚设。
    → 保证压力 0 时至少有两条线索可解锁。

(5) 凶手在压力 0 自曝破绽
    f06 敏感度 0.45 太低，沈玉兰第一句话就说自己在楼梯口碰见周砚青。
    → 调整到 0.6。

(6) 中文数字被当时间
    "[零一二两三四五六七八九十百千万]+" 会把"一推门""一直""一起"全命中，
    每天触发无谓重写，延迟翻倍。
    → 只认"中文数字+点"和"中文数字+量词白名单"。

(7) 网络失败连续重试
    llm 失败返回空串，composer 判"回答为空"再重写，三次超时等于一分钟。
    → 网络/鉴权/超时直接抛 LLMUnavailable，立即兜底不重写。
      只有"生成成功但内容不合格"才重写。

(8) NPC 把玩家认成熟人
    阿蘅躲闪时说"太太这么晚还没歇着"，沈玉兰说"周先生"。
    → system prompt 必须写清"问话的人你不认识，不要称呼姓名"。

(9) 前端五张卡片放不下
    固定 100px 导致第 5 个嫌疑人被裁，玩家以为就四个人。
    → 改 flex 均分 + min-height。

(10) .env 里的密钥
    曾经在聊天里贴过 API Key，已提醒轮换。
    → 密钥只进 .env，.env 在 .gitignore 里，任何文档代码都不许出现。

互动语汇（动作 → 场景反应）：
  换人   → 他从旁边走过来坐下
  提问   → 他微微前倾，台词浮现在他上方

  疲劳   → 他别过头，不再看你

  民国中式风格没有合适的开源素材，硬塞会毁掉调性。

【13】答辩必须能脱稿回答的三个问题
----------------------------------------------------------------
Q1 为什么用三层真相，而不是简单的"真话/假话"？
   因为很多假话不是恶意，是说错。玩家发现"他是真诚地记错了"，
   反而能倒推"谁有动机误导他"，这是更高一层的推理。

Q2 为什么一致性靠数据结构，不靠 prompt？
   因为你没法验证模型有没有记住。知识边界靠 holders 字段，
   说过什么靠谎言账本，冲突靠校验器比对。这三层都不依赖模型自觉。

Q3 压力机制是从哪个体验问题倒推出来的？
   如果 NPC 一律按危险度回答，玩家就只是个提问机器。
   压力让"出示证据"这个动作有后果，玩家才有施压的感觉。
