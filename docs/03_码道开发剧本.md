# 码道开发剧本

> 写给码道的原话。一段一段发，跑通再下一段。
> 原则：**给目标和担心，不给实现细节**。留它自己做决定的余地，你负责挑错。

---

## 开工前（人做的事）

1. 码道工程目录选 `E:\huawei`
2. `AGENTS.md` 已经在根目录，码道会自动读
3. 每段跑通就 `git commit`，message 写你这段想干什么
4. 每段开始前，先说一句**你自己的判断**（"这段我想先做 X，因为 Y"），一行就够

## 第 1 段：数据层

**为什么先做这个**：后面所有逻辑都建立在"剧本能被正确读进来"上。这层不牢，引擎写完也得返工。

```
我要给这个推理桌游做数据层，先读 project/data/scripts/mistvale-inn.json。

需求：
1. 用 pydantic 把剧本读成对象，字段以 JSON 实际结构为准，别自己加戏
2. 加载时做校验。我担心的是这几个地方，写错了明天引擎就跑不起来：
   - 凶手得是真实存在的角色
   - 破案链上的每条事实至少得有一个人知道，否则玩家永远挖不出来
   - 每个人至少知道 5 条事实，不然问什么都是"不知道"，体验直接崩
   - 各种 id 引用不能断
   报错要说清是哪条数据哪个字段错了。只说"数据非法"等于没说。
3. 加个命令行入口能打印这个本子的概况，我要肉眼确认一遍

按 AGENTS.md 来。写完跑测试，把真实输出贴给我。
```

**你怎么审**：别只看测试过没过。改坏一个字段，看报错能不能指出是哪条 `fact`。指不出来就打回去。

## 第 2 段：意图解析 + 知识边界

**为什么现在是这个**：决策层依赖检索结果。检索如果越权（把不该知道的也捞出来），后面怎么调都白搭。

```
下一步做检索，这是整个游戏最不能出错的地方。

玩家问一句话，我要先知道他在问什么（时间？凶器？动机？关系？），
然后只在这个 NPC 知道的范围内找答案——记住，NPC 不知道的东西，
它必须表现得像真的不知道，不能靠模型常识替它补。

这块我会拿单元测试卡死：给一个不掌握凶器信息的角色问凶器，
检索必须返回空。返回一条都算 bug。

中文分词别引入 jieba 之类的依赖，用关键词包含匹配就够了，命中率不够我们再调。
```

**你怎么审**：专门试一个"越权"的提问。问陆明川凶器是什么，如果他答得有模有样，说明知识边界漏了。

---

## 第 3 段：该说什么、该瞒什么

**为什么现在是这个**：这是三层真相落地的地方，也是这游戏和"AI 陪聊"分道扬镳的地方。

```
现在做"说什么"的决策，不涉及措辞，只输出一个决定。

我的设计是：每条事实有个危险度，每个角色有个撒谎倾向，
玩家的施压会降低他开口的门槛——压力越高越容易松口，这是整个游戏唯一的手感来源。

还有个特殊情况要处理好：有些角色知道的是**错的版本**（他确实相信那个错版本）。
这种情况他说出来的是"真话"，不能算撒谎，也不能记进谎言账本。
剧本里 f03 就是这样一条，你可以拿来验证。

阈值、权重这些别硬编码在函数里，抽到 config 去，我后面要调。
```

**你怎么审**：让同一个角色被反复施压，看它的态度是不是真的软下来。一条都不松口，或者第一句就全招，都是手感坏了。

---

## 第 4 段：说人话 + 不自相矛盾

**为什么现在是这个**：到这里能出对话了，也是第一次能看到"像不像游戏"。

```
接上模型，把决策变成人话。三个要求：

1. 民国口吻，第一人称，别超过 80 字，别写"根据我的记忆"这种旁白腔
2. 含糊的时候要含糊得像在躲，不能像在报错
3. 说完之后要能对上——同一个人前面说过的话，后面不能翻脸

第 3 条是重点。我不想靠"提示模型记住"，那不靠谱。
你想想用什么结构能硬保证这一点：他每一次说了什么，都留个档，
下次生成完先跟档案核对一遍，冲突就重写，重写两次还冲突就用模板兜底。

先别追求文采，先保证问十次同一个问题，答案在语义上是一致的。
```

**你怎么审**：同一个问题连问五遍。五次里有两次说法不同，就说明校验没生效。

---

## 第 5 段：走通一局

**为什么现在是这个**：能通过 HTTP 玩完整一局，才算"作品"不是"脚本"。

```
把上面这些串起来，做成能玩的。

一局要能走完：开局 → 提问 → 拿到线索 → 把线索甩给对方 → 指认 → 结算。
提问要流式返回，前端要能一边收一边显示。
出示线索要让对方压力上升，并且立刻重新回答一次——这是玩家唯一能"动手"的地方。

几个不能出错的地方：
- 玩家解锁的线索要自动进线索板，不需要他手动捡
- 结算页要告诉玩家他漏了哪几条关键线索，不能只给个对错
- 密钥走环境变量，别写死在代码里

先存内存里，不做持久化，一局丢了就丢了。
```

**你怎么审**：不看代码，纯用接口走一遍。少一步都不算完。

## 第 6 段：界面

**为什么现在是这个**：引擎稳了再上界面，否则你会花时间给一个错的东西做美化。

```
做前端，一屏放下，三栏。

左边五个嫌疑人，点谁跟谁说话。
中间对话，NPC 的话一个字一个字往外蹦，别一次性糊上来。
右边线索板——这一栏最重要，它是"这是游戏不是聊天"的唯一证据，做出实体物证的质感。

再加个结算页：左边真相时间线一条条亮，右边列出玩家漏掉的关键线索。

用原生 HTML+JS，别引入构建工具。民国悬疑的调子，深底暖字。
```

**你怎么审**：把截图发给我看。AI 做的界面通常"能看但不好玩"，尤其是线索板——那是灵魂。

## 第 7 段：收尾

**为什么现在是这个**：最后一段永远最赶，所以要提前留出时间。

```
最后收尾，三件事：

1. 写一份回归测试：把最容易被问到的几十个问题固定下来，
   每条写清楚"必须出现什么""绝不能出现什么""施压后必须改口"。
   以后每次改引擎都跑一遍，我要看见它真的能拦住回归。
2. README 写清楚：装什么、怎么起、模型怎么配、换剧本怎么换。
   要求是别人拿到能复现。
3. 部署文档：从一台空机器到能访问，每一步都写。

写完按 AGENTS.md 的格式汇报。
```

**你怎么审**：找个没碰过这个项目的人，让他照 README 跑一遍。卡在哪，就补哪。

## 关于"痕迹"

| 时段 | 要做的事 |
|---|---|
| 每段开始 | 说一句自己的判断（为什么现在做这个） |
| 每段结束 | `git commit`，导出对话 |
| 卡住时 | 别急着让它重写，先把报错发过去问它"你觉得自己哪错了" |
| 最后 | 跑 `tools/export_traces.py`，在生成的文档开头手写一段开发复盘 |

**返工记录比顺利通过更值钱。** 别为了让痕迹好看而删掉中间的试错。
