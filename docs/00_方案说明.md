# 雾镇 · AI 原生推理桌游

> 版本：MVP v0.1
> 定位：电子桌游 / 社交推理
> 一句话：**每个 NPC 只知道一部分真相。有人撒谎，有人只是记错了。**

---

## 1. 产品定位

| 项 | 内容 |
|---|---|
| 品类 | AI 原生推理桌游（单人侦探视角） |
| 载具 | Web 单页应用 |
| 一局时长 | 15–25 分钟 |
| 人数 | 1 名玩家 + 5 个 AI 嫌疑人 |
| 胜负 | 玩家指认凶手，结算时展示真相时间线 |

### 与现有产品的区别

| 形态 | 谁在演 | 解决什么 | 没解决什么 |
|---|---|---|---|
| 传统剧本杀 | 真人玩家 + 真人 DM | 社交体验 | 一次性消费、组局难 |
| AI 剧本杀 App | 真人玩家 + **AI 当 DM** | 缺 DM | 剧本仍然一次性 |
| **雾镇（本作）** | 玩家 + **AI 当嫌疑人** | 缺 DM + 缺对手 | —— |
| AI 陪聊 | 玩家 + AI 角色 | 陪伴 | 没有目标、没有胜负、没有重玩性 |

核心差异只有一句：**我们让 AI 变成"有秘密、会撒谎、会记错"的对手，而不是念稿的旁白。**

---

## 2. 核心玩法循环

```
① 提问 ──→ NPC 依据「知识边界」回答
             ├─ 不持有该信息 → 真诚地说不知道
             ├─ 持有但无害   → 直说
             ├─ 持有且敏感   → 回避 / 撒谎（记入谎言账本）
             └─ 持有但记错了 → 真诚地说错话（最有味道的一类）

② 收集线索 ──→ 进入线索板

③ 出示线索 ──→ 目标 NPC 的「压力值」上升
             └─ 压力越高，越容易松口改口

④ 发现矛盾 ──→ 两个 NPC 对同一件事说法不一

⑤ 指认凶手 ──→ 结算：真相时间线 vs 你的推理
```

**③ 是整个游戏的手感来源。** 没有它，玩家只能被动记录；有了它，玩家有"逼供"的动作，桌游的博弈感就出来了。

## 3. 三层真相模型（技术核心）

这是本作和"让 GPT 扮演 NPC"的根本区别。

```
truth      客观事实
belief     NPC 相信的事实（可能是错的）
utterance  NPC 说出口的话（可能撒谎）
```

三种错位 → 三种角色性格：

| 状态 | 含义 | 玩家感受 | 剧本中的典型 |
|---|---|---|---|
| belief=truth, utterance=truth | 诚实 | 可靠证人 | 陆明川 |
| belief=truth, utterance≠truth | 撒谎（有动机） | 他在骗我 | 沈玉兰 |
| belief≠truth, utterance=belief | **真诚地说错话** | 他搞错了？谁让他搞错的？ | 周砚青 |

第三类是本作最值钱的设计：玩家发现"这个人不是在骗我，是他记错了"，反而获得更多信息——因为可以倒推"谁有动机误导他"。

## 4. MVP 范围（明确做什么 / 不做什么）

### 做（P0）

- [x] 1 个剧本《雾镇旅馆》，5 个嫌疑人，固定真凶
- [x] 三层真相模型（truth / belief / utterance）
- [x] 知识边界：NPC 只知道自己持有的 fact
- [x] 应答决策：直说 / 回避 / 撒谎（按敏感度 + 压力）
- [x] 谎言账本 + 一致性校验（回答前后不矛盾）
- [x] 线索板 + 出示线索 → 压力值机制
- [x] 指认 + 结算页（真相时间线对比）
- [x] 30 条高频问题的回归测试集

### 不做（P1 以后）

- [ ] 凶手随机 / 角色池组合（需为每个角色写独立犯案时间线，工作量大）
- [ ] AI DM 动态难度调节
- [ ] 多人共玩 / 房间同步
- [ ] 语音输入输出
- [ ] 剧本编辑器

> **注意**：P0 里的"重玩性"靠两个东西撑：**NPC 撒谎策略带随机扰动** + **线索发现顺序不同**。虽然剧本固定，但每一局玩家听到的谎话版本不一样。这一点在答辩时要主动说明，不要等评委问。

## 6. 答辩三句话（背下来）

1. > "传统剧本杀是一次性消费品，一个本玩过就废。我们让 AI 当嫌疑人，同一套剧本，每个人每局听到的谎话都不一样。"

2. > "我们不让 AI 说假话，我们让 AI 说**它自己相信的错话**。玩家要分辨的不是谁在骗人，而是谁被误导了——这是两个完全不同的推理层级。"

3. > "一致性不靠 prompt，靠三层数据结构：知识边界决定它知不知道，谎言账本决定它说过什么，校验器保证它不会自相矛盾。"

## 7. 演示脚本（2 分钟）

| 时间 | 画面 | 台词 |
|---|---|---|
| 0:00–0:15 | 暴雪旅馆，一具尸体，5 个嫌疑人 | "1937 年，雾镇。老板死在书房，五个人都说自己没上过二楼。" |
| 0:15–0:45 | 问沈玉兰三句 | 她说 22:45 就离开了书房 |
| 0:45–1:10 | 问周砚青 | 他"记得"23:10 听见争吵 —— **时间对不上** |
| 1:10–1:40 | 出示「阿蘅的目击」给沈玉兰 | 她改口："我是 23:00 出来的，但我没杀他" —— **第一处破绽** |
| 1:40–1:55 | 指认 → 结算页 | 真相时间线逐条亮起，标红玩家漏掉的两条 |
| 1:55–2:00 | 重开一局，同一句提问 | 她的说法变了 —— **"同一剧本，不同的谎"** |

最后 5 秒是收尾钩子。

## 8. 已知风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 一致性调不稳，NPC 自相矛盾 | 致命 | 校验器 + 30 条回归测试，每次改完必跑 |
| LLM 延迟高，演示卡顿 | 严重 | 流式输出；高频问题走模板缓存 |
| 玩家问出剧本外的问题 | 中 | `out_of_scope` 兜底：宁可装傻，不许编造 |
| 评委认为"就是个聊天游戏" | 中 | 强调线索板 + 压力值 + 结算，这是游戏机制不是聊天 |
| 剧本内容被质疑"太简单" | 低 | 主动说明这是 MVP，架构支持任意剧本扩展 |
