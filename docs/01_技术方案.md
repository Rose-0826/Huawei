# 技术方案 · 雾镇 MVP

---

## 1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Python 3.11 + FastAPI | 异步、自带 OpenAPI 文档、部署简单 |
| 模型 | 华为云 MaaS（DeepSeek / GLM） | 呼应"与华为云服务结合"，且比赛有代金券 |
| 存储 | SQLite（MVP）→ RDS for PostgreSQL（P1） | 零配置起步，接口一致可平滑迁移 |
| 前端 | Vue 3 + Vite（或纯 HTML + 原生 JS） | 单人项目，纯 HTML 更快出效果 |
| 实时 | SSE（非 WebSocket） | 单向流式输出，SSE 足够且更稳 |
| 部署 | 华为云 ECS + Nginx + systemd | 对应"部署上线 +3" |

> **不要引入 LangChain / LangGraph。** 协商与问答的核心逻辑要自己写，代码短、可解释、能贴到 PPT 上。框架反而会让评委看不清谁在决策，也增加调试成本。

## 3. 数据模型

```python
from dataclasses import dataclass, field

@dataclass
class Fact:
    id: str
    text: str                     # 客观事实
    topic: list[str]              # time / weapon / motive / relation / event
    holders: list[str]            # 谁知道这条
    sensitivity: float            # 说出后对自己多危险 0~1
    belief: dict[str, str] = field(default_factory=dict)   # npc_id -> 他相信的错误版本
    source_of_error: str | None = None                     # 谁误导了他

@dataclass
class Role:
    id: str
    name: str
    public: str                   # 公开身份
    secret: str                   # 秘密
    goal: str                     # 目标
    lie_propensity: float         # 撒谎倾向 0~1
    relations: dict[str, dict]    # npc_id -> {type, trust}
    is_culprit: bool = False

@dataclass
class Testimony:
    """NPC 说过的每一句断言，用于一致性校验"""
    npc_id: str
    fact_id: str
    said: str
    is_lie: bool
    round: int
```

**运行时状态**

```python
@dataclass
class GameState:
    script: Script
    round: int = 0
    pressure: dict[str, float] = field(default_factory=dict)   # npc_id -> 0~1
    testimonies: list[Testimony] = field(default_factory=list)
    lies: dict[str, dict[str, str]] = field(default_factory=dict)  # npc_id -> {fact_id: 谎话版本}
    clues: list[str] = field(default_factory=list)             # 玩家已获得的 fact_id
```

## 4. 核心算法

### 4.1 主流程

```python
async def answer(npc: Role, question: str, st: GameState) -> str:
    intent = await parse_intent(question)            # -> {topic, about_npc, about_item}
    cands  = retrieve(npc, intent, st.script)        # 只在自己 holders 里筛
    if not cands:
        return await deflect(npc, intent)            # 兜底：装傻，绝不编造

    views = []
    for f in rank(cands, intent)[:3]:
        view = f.belief.get(npc.id) or f.text        # 先看他信什么
        if f.sensitivity >= threshold(npc, st):
            view = await distort(npc, f, view)       # 撒谎（LLM 生成假版本）
            st.lies.setdefault(npc.id, {})[f.id] = view
        views.append((f.id, view))

    draft = await compose(npc, views, intent, st)    # 自然语言
    draft, ok = await verify(draft, npc, st)         # 一致性校验
    if not ok:
        draft = safe_fallback(npc, views)            # 模板回退
    return draft
```

### 4.2 压力阈值（松口机制）

```python
def threshold(npc: Role, st: GameState) -> float:
    """压力越高，越容易说实话"""
    base = 0.9 - 0.5 * npc.lie_propensity
    p = st.pressure.get(npc.id, 0.0)
    return clamp(base - 0.4 * p, 0.1, 0.95)
```

- 初始：撒谎倾向越高，阈值越高（越容易骗人）
- 每次成功出示相关线索，`pressure += 0.25`（上限 1.0）
- 效果：出示 2 条相关线索后，凶手开始改口

**这是整个游戏唯一的"操作感"来源，务必调好手感。**

### 4.3 一致性校验

```python
async def verify(draft: str, npc: Role, st: GameState) -> tuple[str, bool]:
    claims = await extract_claims(draft)             # 抽成 (fact_id, 断言)
    for c in claims:
        # 1) 与自己的谎言账本比对
        prior = st.lies.get(npc.id, {}).get(c.fact_id)
        if prior and contradicts(c.text, prior):
            draft = await rewrite(draft, keep=prior)
            return draft, True
        # 2) 与自己之前说过的比对
        for t in st.testimonies:
            if t.npc_id == npc.id and t.fact_id == c.fact_id and contradicts(c.text, t.said):
                draft = await rewrite(draft, keep=t.said)
                return draft, True
    return draft, False
```

重写最多 2 次，仍冲突则用 `safe_fallback`（模板句式），宁可含糊，不可自相矛盾。

### 4.4 意图解析（省 token 的规则优先）

```python
TOPIC_RULES = {

    "weapon":  ["凶器", "拨火棍", "镇纸", "用什么", "伤"],
    "motive":  ["为什么", "动机", "恨", "钱", "账", "遗产"],
    "relation":["认识", "关系", "谁", "儿子", "女儿", "妻"],

```

## 5. API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/game` | 开局，返回剧本公开信息 + 5 个嫌疑人 |
| POST | `/api/game/{gid}/ask` | 提问 `{npc_id, text}` → SSE 流式回答 |
| POST | `/api/game/{gid}/present` | 出示线索 `{npc_id, clue_id}` → 返回新回答 + pressure |
| GET | `/api/game/{gid}/state` | 当前状态（线索、压力、轮次） |
| POST | `/api/game/{gid}/accuse` | 指认 `{npc_id}` → 结算数据 |

SSE 事件格式：

```
event: token
data: {"text": "我……"}

event: meta
data: {"clue_unlocked": "f05", "pressure": 0.25}

event: done
data: {}
```

`meta` 事件是前端更新的关键——**NPC 说出关键信息时，自动解锁线索卡片**，视觉反馈立刻出现。

## 6. 前端

三个区域，一屏放下：

```
┌──────────────┬────────────────────┬──────────────┐
│  嫌疑人列表   │      对话流         │   线索板      │
│  5 张卡片     │   气泡 + 打字机     │  可拖拽卡片   │
│  压力条       │   输入框            │  拖到对话框=  │
│  已知线索数   │                    │  出示线索     │
└──────────────┴────────────────────┴──────────────┘
```

**线索板是本作"是游戏不是聊天"的视觉证据，优先级高于任何动画。** 拖拽实现不了就先做"点击线索 → 出现【出示】按钮"，效果一样。

状态只有四个：`idle / thinking / streaming / ended`。

## 7. 回归测试（关键资产）

`data/regression/questions.json` 里放 30 条，每次改完引擎跑一遍：

```json
[
  { "npc": "r1", "q": "昨晚十点半你在哪", "expect_not_contain": ["22:30 在书房"] },
  { "npc": "r2", "q": "你听见争吵了吗", "expect_contain": ["争吵"] },
  { "npc": "r1", "q": "你袖子上是什么", "expect_change_after_pressure": true }
]
```

断言分三类：**不能出现的错话**、**必须出现的关键词**、**施压后必须改口**。

这 30 条同时是 PPT 里"我们做了 30 轮一致性回归测试"的证据。

## 8. 部署

```bash
# ECS 上
git clone <repo> && cd project
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
export MaaS_API_KEY=xxx
nohup uvicorn app.main:app --host 0.0.0.0 --port 8000 &

# Nginx 反代 80 -> 8000，前端静态文件由 FastAPI 直接挂载
```

需要注意：

- 模型密钥走环境变量，**绝不进仓库**
- 加一个 `/health` 接口，方便演示前自检
- 演示机提前跑一遍，把成功 trajectory 的答案缓存下来，网络挂了好降级
